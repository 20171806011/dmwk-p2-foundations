# P2-A3 — Claim-to-evidence map

This map separates handwritten conditional proofs, exhaustive finite-domain checks, fixed-seed properties, actual arithmetic observations, constructive counterexamples, source identity, and independent review. None of these is relabeled as a complete machine proof. P1/P2-A1/P2-A2 are read-only prerequisites, not stages rerun by A3.

## Three different contracts

| Contract | Meaning and evidence | What it cannot authorize |
|---|---|---|
| **ALG** | Exact decoded endpoint difference `Delta_eff = W' - W` annihilates a supplied generator matrix. With independently proved global coverage, T1/T2 make this equivalent to exact full linear-output equality on the protected set or a sufficient condition for a conservative containing space. Implemented by [linear_contracts.py](linear_contracts.py). | The diagnostic does not establish global-domain provenance or floating execution equality. It always records `global_domain_provenance_verified: false` and `authorizes_bitwise_commit: false`. |
| **BOUND** | For a specified stored input, endpoints, bias-first arithmetic graph and numerical policy, exact decoded output change is decomposed into effective affine change and old/new execution errors. [bounded_contracts.py](bounded_contracts.py) calculates absolute local-roundoff bounds. | This implementation does not authorize a live patch or establish uniform coverage. A positive bound requires a separate separation/encoding argument to imply raw equality; T3 states that sufficient condition. |
| **BIT** | The checker-owned complete finite registry supplies the domain, sites and invariant; [certificate_kernel.py](certificate_kernel.py) recomputes old/new raw outputs and transitions over that domain before accepting a bound endpoint/version transaction. | This is not arbitrary-network, arbitrary-domain, concurrent-runtime or compiler certification. A caller cannot turn samples into a complete domain by changing a label or recomputing a digest. |

ALG and BIT are **non-nested** predicates in general. Exact annihilation may fail under rounded execution. Conversely, a nonzero exact change can be rounded away on every actually legal protected input, even when their span has full rank. Neither direction is inferred solely from a rank calculation or one basis probe.

## Counterexamples and blocked inferences

The detailed constructions are in [Counterexamples](P2_A3_Counterexamples.md), with raw words and exact residuals in [counterexample_results.json](counterexample_results.json). That file records eight deterministic classes in two formats, with extra boundaries separately identified.

| Case | Evidence location | Conclusion |
|---|---|---|
| **Commit rounding changes the patch** | Record `A3-C1_commit_endpoint_difference`; T3 proposition; independent `commit_effective_delta` pointwise fixture. | For old row `(2^p,0)` and ideal `(1,-1)`, target commit gives effective `(0,-1)`. The protected output changes by `-1`. Testing the ideal proposal is insufficient. |
| **Zero at the basis, nonzero at another legal activation** | `A3-C2_basis_zero_but_legal_subnormal_nonzero`; T3 proposition; independent subnormal fixture and complete-domain refusal. | Rounded thirds projector gives zero at `ones(3)` but raw `0x1` in every output at `eta*ones(3)`. Both are explicitly legal stored inputs; exact decoded annihilation holds for both. Floating basis probes do not extend by linearity. |
| **Omitted shared site** | `A3-C3_shared_call_site_omission`; algebra `shared_site_omission`; split-model refusal. | Two locally rank-one spaces can merge into full rank. The strong duplicated-input patch fails a site preparing `(u,0)`. All sites in the common physical frame matter. |
| **Omitted reachable state** | `A3-C4_reachable_state_omission`; certificate domain/state tampering refusals. | Testing the current state does not prove the common invariant envelope. A certificate must cover every legal state/input context, not only observed prefixes. |
| **Unmodeled A-to-D input influence** | `A3-C5_unmodeled_A_to_D_input_feedback`; algebra `changed_inputs`; T4 premises. | Even zero weight change does not ensure equal output when compared inputs differ. An A-output change may alter the D input unless the interface prevents or models that channel. |
| **Bias omitted or incorrectly compressed** | `A3-C6_bias_omission`; algebra `affine_basis_compression`; independent affine subset checks. | Actual activations `{0,1}` and `{1}` have the same unaugmented span but different augmented constraints. Joint bias equality cannot be inferred by appending one to an arbitrary ordinary basis. |
| **Changed reduction tree** | `A3-C7_changed_reduction`; rejected graph/policy changes. | Exact-zero dot `(2^p,1,-2^p,-1)` with unit inputs executes to `-1` in the reference order, while the alternate reduction gives zero. A graph identifier is part of the semantic contract. |
| **Changed FMA/fusion policy** | `A3-C8_fusion_policy_change`; independent FMA/fusion certificate mutations. | Separate and modeled fused arithmetic differ for the recorded inputs. The fused result is an exact software one-round reference, not native FMA certification. Unsupported optimizations are refused. |
| **Full-rank finite BIT does not imply ALG** | Extra record `A3-X1_full_rank_bitwise_equivalence_not_algebraic_null`; T3 proposition; production `bitwise_without_algebra_witness`; independent examples in both registered stateful models. | `I_2 -> ((1,eta),(0,1))` preserves every protected raw output on `{0,(1,1),(1,0)}`, whose span has rank two, but has a nonzero exact residual. At A input `(0,1)` the retained subnormal produces a changed output. Full rank eliminates exact annihilators, not every finite-domain rounded observational equivalence. |

These cases refute the indicated unconditional implications. They do not invalidate the qualified algebra theorem, the pointwise identity, or the fixed-model trace induction.

## Certificate binding, closure and refusal evidence

The certificate payload is bound to raw old/new endpoint words, exact decoded effective difference, fixed bias, model/format identity, physical matrix and protected sites, full activation and state/input domain, invariant identifier, graph, numerical policy, trusted schedule, expected weight version and implementation identity. The trusted checker reconstructs the registry descriptor and proof by evaluating both endpoint graphs and transitions. Matching a supplied digest is not sufficient.

The domain is not learned from traces. For the stateful models, the checker enumerates both initial bits and all legal `(q,u)` bit pairs. The mathematical XOR invariant proves that every permitted future transition stays within that declared envelope. Every certificate is checked against the current bank/version; successful global-domain certificates can survive legal state advancement because they were not restricted to a sampled current state. Replayed stale certificates are refused after the endpoint/version changes.

Production and independent checks modify fields and recompute their hashes. They cover missing sites/activations/initial states, sample-only labels, wrong endpoints/effective deltas, forged proof or implementation identities, changed domain/invariant/sharing, graph order/FMA/fusion, changed numerical policy/schedule, malformed or noncanonical JSON, duplicate keys, invalid input words, unsafe candidates, reinitialization and callback-capable argument subclasses. Rejection preserves the previous snapshot; complete validation precedes one bank publication. The version-exhaustion rule is explicit.

These mechanisms assume serialized trusted local calls, immutable checked primitive data and no arbitrary mutation of private interpreter memory or modules. The registry and its connection to execution are part of the trusted mathematical/implementation contract. General concurrent atomicity, an adversarial Python runtime, cryptographic authorization and arbitrary user-supplied invariant proofs are not claimed.

## Dependencies, evidence identity and stopping boundary

[dependency_baseline.json](dependency_baseline.json) captured **341** prior files before A3 work, excluding the listed repository/cache/virtual-environment internals. [a3_runtime.py](a3_runtime.py) resolves only the declared A2 arithmetic modules and checks canonical import paths. Existing definitions, proofs, contracts and reviews are inherited read-only. No previous-stage verifier is invoked by the A3 driver.

[P2_A3_Errata.md](P2_A3_Errata.md) records dependency clarifications separately; it does not overwrite prior evidence. The current interface examination found no contradictory prerequisite theorem. It is not a new full audit of all P1/A1/A2 claims. Main and independent source hashes establish which source files were exercised; hashes do not prove correctness. Reproduction and final integrity outcomes belong to their actual result records, not to an assumed success from this table.

BF16 execution is **software nearest-even rounding with gradual underflow and canonical zero**. FP32 arithmetic uses local scalar CPU operations audited against exact rational rounding. No native BF16, GPU, arbitrary BLAS/GEMM replacement, unsupported FMA/reassociation, general concurrency or complete compiler/runtime machine proof is certified. The general program-lifting theorem retains its stated interface assumptions; this is not completion of the whole P2-C combination.

A4 must distinguish exact annihilator dimension from finite-format endpoint realizability and complete-domain executable equivalence. The full-rank tiny-edit witness makes that distinction essential. This A3 evidence does not claim an A4 capacity classification or learning-performance result.
