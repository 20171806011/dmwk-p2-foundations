## Required distinctions before measuring capacity

1. Fix the quantity being measured: dimension of the abstract algebraic annihilator, rank of one update, number/geometry of representable endpoint edits at a specified old bank, size of a finite-domain bitwise-equivalence class, or existence of an observable A response. These are not interchangeable.
2. Fix each physical matrix's shape, orientation, all shared call sites, common input coordinates, bias policy and a globally justified activation domain or conservative upper space. Unknown low sampled rank remains a lower bound, not protection evidence.
3. Use the actual decoded endpoint difference W'-W. A proposal can be altered by commit rounding, and a difference of representable endpoints need not be a representable standalone increment.
4. Separate ALG from BIT. Full exact rank forces the exact linear annihilator to zero. A3's full-rank split-domain example nevertheless admits a nonzero stored edit whose floating outputs agree on every legal D input and differ on an A input. Thus full rank does not by itself classify executable observational capacity.
5. Bind any executable-capacity claim to a graph, arithmetic policy, complete legal state/input domain, same-snapshot update rule, version protocol, and local-to-program lifting premises. A different activation preparation, FMA rule or output observation changes the question.
6. Require a nonzero actual endpoint change and a changed admitted A response when claiming nontrivial editability. Separately define what stronger evidence would establish useful learning, robustness, margin or task performance; A3 establishes none of those performance properties.
