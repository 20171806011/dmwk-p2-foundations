# P2-A4 — Claim-to-evidence map

This map separates general mathematical proofs, finite exact computations, finite floating-point checks and execution-authority claims. The definitions and complete proofs are in [Definitions](P2_A4_Definitions.md) and [Theorems](P2_A4_Theorems.md). All counts below are read from the actual component JSON records. Repeated checks of the same family are independent corroboration, not additional distinct endpoints.

## Capacity objects and their evidence types

For an n-by-d bank, let V be the proved global protected activation span, r=dim(V), and c=d-r. The four capacity notions are not four nested vector spaces:

| Object | Appropriate quantity | What the evidence must establish |
|---|---|---|
| Exact algebraic annihilators U(V) | Dimension nc; individual update rank; prescribed-response feasibility | Exact field algebra and a proof that V contains all required activations |
| Admitted stored endpoints E | Finite cardinality; canonical raw words; exact decoded difference W'-W | Format, old endpoint, masks and endpoint policy |
| Fixed-graph protected equivalence E_BIT | Finite cardinality or individually checked certificates | Full declared raw protected domain, graph, numerical policy, effects, version and schedule premises |
| A-response image of a specified feasible subset | Exact response dimension, or finite raw signature count | Specified A inputs and outputs, total execution and the precise feasible subset |

E_ALG and E_BIT are both subsets of a specified stored family E; neither generally contains the other. A response image depends on the selected subset and target domain. The number nc is not the rank of each update, the number of finite endpoints, or a learning-performance measure.

## Theorem ledger

The T1–T8 proofs are handwritten mathematical arguments. No Lean/Coq theorem checking and no SMT query are claimed in this stage.

| Claim | General proof and prerequisites | Finite implementation evidence | Scope boundary |
|---|---|---|---|
| **T1: exact dimension, rank budget and attainment** | Basis extension proves dim U(V)=nc and rank Delta<=min(n,c); Delta=G P_perp with rank G<=k gives min(k,n,c), with a construction attaining every allowed rank. Fixed-generator orientation and the nonlinearity of an active rank constraint are proved separately. | `algebra_results.json`: 192 rank-attainment budget cases, 80 seeded rational rectangular cases, explicit rank-cap and orientation examples. `review_results.json/algebra`: 1,296 direct H/Delta pairs checked using determinant/minor rank and direct products. | Abstract Q/R maps; no endpoint representability or bitwise authorization follows. |
| **T2: global sharing, monotonicity and provenance** | Annihilation of a sum equals simultaneous annihilation of its summands. Nested protected spans decrease exact freedom by n times the rank increase. Finite ALG monotonicity fixes the old bank and endpoint family; BIT monotonicity requires nested raw contexts at fixed execution contracts. | Named algebra cases: `local_low_rank_global_full_rank`, `conservative_overfreezing`, `sample_underprotection`, `protection_chain`. The alphabet admits finite values with one canonical zero and rejects negative-zero input encodings, infinities and NaNs. Arithmetic zero normalization is part of the fixed policy. The large N^2 counts are justified by independent storage choices and exact observation of those choices under T8; neither format's entire pair space was enumerated.

## Acceptance and protected-state evidence

Capacity analysis is not an authorization to commit. The exact algebra module explicitly reports that it has not verified global activation provenance, endpoint feasibility or bitwise safety. Live acceptance remains the inherited A3 trusted serial interface, binding the old and new endpoints, registered full domain, fixed graph and numerical policy, version, state and scheduling assumptions.

The discrete tests exercise that interface without rerunning the prior suites. The 38 expected refusals include malformed or changed certificate material, stale/version mismatches, omitted protected coverage, unsupported contracts and unsafe candidates; snapshots are checked for unchanged protected state after refusal. The independent review separately checks stale replay, omitted sites, sample-domain claims, changed policy and changed schedule. These finite transaction tests do not prove security against arbitrary host-memory tampering, concurrent mutation or untrusted API implementations.

## Limits and evidence not claimed

The general results assume the fixed protected D program, admissible initial states and legal input domain, global call-site coverage, identical protected initial state/input/schedule, bit-preserving storage and the prescribed synchronous/serial commit semantics. Algebraic claims use Q or R. BF16 experiments use a software rounding model; FP32 experiments use the audited local CPU separate-operation path. Native BF16, GPU kernels, general concurrency, arbitrary compiler optimization, fusion and FMA changes are not certified.

No claim of useful learning performance, universal finite-format capacity classification, a completed compiler, hardware optimality, or a complete P2 composition theorem is made. B1 remains a next-stage handoff; A4 does not implement it. Prior-stage sources are used read-only through the runtime loader; their old test suites are not rerun by the A4 component scripts.
