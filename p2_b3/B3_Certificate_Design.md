# B3 read-only propagation certificate: design before implementation

This design is saved before certificate code. Implementation waits for the root mathematical checkpoint and the core propagation interface. Prior research and prior optimizers remain read-only.

## Fixed claim

The concrete receipt uses the full-output absolute **infinity norm**. Generic norm theorems do not make an unimplemented L2 conversion available. The receipt is detached evidence and always declares no live authority, no BIT/ALG authorization and no permission to replace B1's selected update contract.

The trusted model registry must fix physical matrix identifiers and shapes, every ordered call site and its sharing map, fixed graph/nonlinearities, canonical BF16/FP32 policy, bias treatment, legal input histories, initial-state relation, observation ports, schedule, and original/perturbed domain geometry. All physical old/new stored endpoints and biases are explicit. A finite horizon is bound. A claimed infinite-time conclusion would require an independently named invariant/uniform theorem and is not inferred from a finite trajectory.

## Recomputed obligations

The producer invokes the core's certified propagation and domain-containment proof. The checker repeats that computation against externally expected model, format, endpoint banks, biases, initial relation, horizon, version, context and budget. It rejects insufficient budgets, unknown domains, sampled provenance, incomplete call sites, missing schedule, changed graph/FMA policy, changed endpoints/state or observation ports, stale identity context and inconsistent numerical proof records. Source hashes identify the specified implementation but do not authenticate callers or prove a caller-provided domain.

Every accepted result must prove containment for both executions at every stage/time in its claim. A certificate for the original program's inputs alone is insufficient for perturbed recurrent propagation. Totality/no-overflow obligations are part of this proof. The fixed finite input domain and its containing boxes are distinguished; no observed trajectory maximum is silently used as an invariant.

## State identity and transaction separation

Where state context is supplied, the full primitive snapshot and schedule are bound. Schema/identity checking is not live-state authentication, an arbitrary program-invariant proof, or protection against concurrent mutation. Exact context compatibility with physical endpoint banks will be fixed after the core descriptor is available and stated explicitly.

New B3 integration checks use the unchanged B1 API to establish that a B3 numeric receipt cannot be committed. The B1 fixture will have nonzero first/second moments and a nonzero protected tick count, so refusal must preserve weights, moments, optimizer time, version, state and ticks. This is one new interface-boundary fixture, not a replay of frozen B1 training. The 21 frozen BIT-equal/ALG-failing refusals and the FP32 AdamW zero-progress result are preserved through read-only JSON inspection.

## Deliverables and evidence

Planned files: `propagation_certificate.py`, `verify_certificates.py`, `certificate_results.json`, `P2_B3_Certificate_Spec.md`. Main receipt tests, independent review, handwritten universal proofs, complete finite enumerations and seeded cases remain separately labeled. Seeded tests use 20261114. The root aggregate handles foreign-directory reproduction and prior-evidence integrity checks. No B4 or live bounded-policy implementation is included.
