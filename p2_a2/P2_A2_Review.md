# P2-A2 — Independent adversarial review

## Scope and disposition

This review examined the four conditional mathematical results in [P2_A2_Theorems.md](P2_A2_Theorems.md), their contracts in [P2_A2_Definitions.md](P2_A2_Definitions.md), and the exact, numerical, and structural implementations. The reviewer used separately written finite oracles and challenged the interfaces and numerical assumptions. P1 and P2-A1 were read only where their interfaces were needed; their previous suites were not rerun and their deliverables were not changed by this review.

**Disposition:** no unresolved blocking contradiction was found within the final stated contracts. This is a review judgment backed by the finite checks below, not a machine-checked proof of Python, NumPy, LAPACK, hardware, or all possible matrices. The conclusions remain conditional on a globally valid protected activation space, the declared numerical policy, and the trusted structural API.

The completed independent verifier is [verify_review_checks.py](verify_review_checks.py). Its actual output is [review_results.json](review_results.json). The JSON binds the reviewed production modules and the independent verifier to SHA-256 digests. It also identifies the unchanged P1 execution helper by digest. A changed source requires an affected-check rerun before this evidence can be attributed to it.

## Mathematical audit

| Result | Reviewed obligation | Assessment and boundary |
|---|---|---|
| T1: exact projection | Rational full-column basis, invertibility of the Gram matrix, symmetry/idempotence, correct kernel and image, agreement of column-basis and nullspace constructions, zero/full-rank cases | The handwritten proof establishes the exact rational construction and its real-linear extension. It does not make a stored rounded matrix an exact projector. |
| T2: update space and capacity | Characterization of every annihilating row by the complement projector, dimension and rank bounds, constructive learning response outside the protected span | The algebraic statements follow for the declared global protected space. An unproved sample span cannot be substituted. Algebraic capacity does not imply a safe stored update. |
| T3: numerical perturbation | Separate projector, candidate-product, commit/storage, and old/new execution errors; exact local telescoping; conditional relative-error bound | The pointwise inequality is valid for the same stored operands and declared arithmetic. The implementation uses exact rational upper bounds. A positive norm bound or a basis residual is not a bitwise invariance certificate. |
| T4: structural safe route | A fixed sparse execution graph excludes the mutable cell from every D-path read; immutable bank publication; legal Boolean state feedback; equal initial state/input/schedule induction | The theorem supplies arbitrary finite-horizon D equality for this graph and API. It is not a theorem that arbitrary projected dense patches are safe. |

The optional representability proposition was checked separately: with `a=2^p-1`, the line generated by `(a^2,-a,1)` contains no nonzero vector whose three coordinates are all individually representable in the specified p-bit format. The odd-significand argument gives this conclusion. It does **not** rule out a difference of representable endpoint weights: `(-1,0,0)` and `(a^2-1,-a,1)` provide such endpoints. No floating execution invariance is inferred from that difference.

No Lean/Coq proof or SMT result was produced by this independent reviewer. The universal mathematical statements remain handwritten proofs. The checks below are finite implementation evidence.

## Findings and corrections

1. **Apparent FP32 SVD did not establish FP32 computation.** In the installed NumPy 2.3.5 public SVD path, float32 inputs are internally promoted and outputs cast back. The final implementation explicitly selects the compiled `f->fff` gufunc for the single-precision experiment and records this dispatch. The private API is version-specific. Output dtype alone is no longer the precision evidence.

2. **Rank cutoffs could disagree with their recorded values.** NumPy weak-scalar conversion can round a Python binary64 cutoff when comparing it to a float32 singular-value array. The final code widens the singular values before comparing. An independent identity-matrix boundary with cutoff `1-2^-53` now returns rank two and uses the recorded cutoff. This correction makes the selected numerical rank reproducible under its stated rule; it does not certify exact rank.

3. **An optional candidate-storage probe overrestricted the declared commit.** Under a single-final-rounding contract, `W=-Fmax` and ideal increment `2*Fmax` have finite committed result `Fmax`, although the increment itself is not storable. The final code treats standalone increment storage as an optional probe and accepts the valid final sum. The result records the distinction from a native stored-increment addition.

4. **Audit objects created a reentrancy path.** A user-supplied counter or list subclass could execute callbacks during increment or event append. The final structural API validates the exact audit type, exact nonnegative integer counters, and a plain list before executing D/A operations. Independent hostile-counter and hostile-list checks confirm refusal without invoking callbacks or changing the bank. Single-threaded use alone would not have closed this issue.

5. **Non-finite numerical diagnostics needed explicit treatment.** Solver outputs and computed rank thresholds are checked for finiteness. An overflowing threshold is refused. An overflowing condition diagnostic is recorded as unavailable with a reason, not as a valid finite certificate or JSON Infinity.

6. **Nonrepresentability was not sufficient to claim kernel leakage.** For the thirds projector, the stored coefficients differ from the exact orthogonal projector, but the decoded row sums remain exactly zero. The final analysis preserves this fact and supplies separate genuine kernel-breaking examples. The independent oracle checks a span generated by `(1,3)`, whose quantized projector has nonzero exact residual in both formats.

7. **A zero result on a generating basis did not establish protection on all legal activations.** The stored thirds projector gives zero under the fixed floating execution at `(1,1,1)`, but gives one smallest positive subnormal in every output at `(eta,eta,eta)`. Both inputs can be explicitly legal members of the same protected span; exact decoded products vanish for both. The independent word-search oracle reproduced this counterexample and the rejection of a relative-only gamma bound.

The implementation also makes the ideal candidate, standalone stored increment, and effective update `W'-W` distinct. This distinction is necessary both for the quantitative error bound and for any representability/capacity claim.

## Independent methods and actual finite coverage

The independent verifier imports production interfaces but does not import or reuse the production verification assertions.

- **Exact projectors:** an independent determinant/minor/cofactor construction checks all **512 binary 3-by-3 matrices** against both production exact constructions. The ranks are 1 matrix of rank 0, 49 of rank 1, 288 of rank 2, and 174 of rank 3. Six additional empty, repeated, near-dependent, and rational fixtures cover edge cases. A separate learning-response example and a merged-call-site counterexample are checked.
- **Target rounding:** a binary search over monotonically ordered positive IEEE words supplies a different exact RNE reference. It checks **21 rational values and 2 overflow refusals per format**. It independently reconstructs the ordered zero-dot counterexample, the effective-update counterexample, the thirds preservation case, and a genuine quantized-projector residual.
- **Stateful structural route:** for each format, both initial Boolean states and all 32 length-five input strings produce **64 paired traces**, **320 protected tick pairs**, and **320 interleaved commits**. The unchanged and updated executions are compared with an independently coded Boolean XOR recurrence. Across the two formats this is 128 paired traces, 640 tick pairs, and 640 commits. The mutable coordinate also demonstrably changes the A response.
- **Public API refusals:** **14 refused operations per format** leave the bank snapshot unchanged. Cases include protected writes, negative zero, NaN/infinity, bool masquerading as a word, stale versions, changed routes/policies, invalid inputs/audits, callback-capable audit contents, and reinitialization. Prior snapshots remain unchanged after later accepted commits. These checks concern the published API and its stated trust boundary.
- **Numerical bounds:** one independently reconstructed T3 example per format has output difference `(-1,0)` and is contained by the reported exact upper bound. Additional checks cover an unstorable ideal increment with a valid final sum, subnormal halfway rounding, retained nonzero subnormals, and absence of an invalid relative bound. The basis-versus-small-activation counterexample is checked in both formats.
- **Rank/precision boundaries:** the independently exact full-rank matrix `((1,1),(0,2^-30))` has default numerical rank two in the tested FP64 route and one in the true single-precision route. Converted-input exact rank remains two. The explicit single-precision dispatch, cutoff comparison boundary, and refusal of an overflowing threshold are checked.

These deterministic checks have no random sampling component of their own. Fixed-seed production experiments are separately recorded by their verifiers; this report does not add their counts to the independent counts or imply that the combined observations prove a universal claim. Actual elapsed cost is recorded in `review_results.json`; no performance advantage is claimed.

## Remaining assumptions and limitations

The global protected space must contain every allowed activation at every shared D call site in common physical coordinates. A full-rank merged space leaves no exact complement capacity even when individual call sites have smaller spans. This provenance requirement is not established by a small residual or a finite sample.

The exact `Matrix` and `Projection` objects are mathematical values, not authorization capabilities. Frozen dataclass conventions alone are not treated as an immutable security boundary. The structural updater accepts validated raw primitive word tuples, makes its own protected-slot checks, and does not trust a caller-supplied projector or certificate.

T3 remains pointwise. A uniform guarantee needs a proven legal-input bound and uniform execution-error control, or complete finite activation coverage. Numerical SVD rank thresholds remain heuristic decisions with recorded diagnostics. An exact null product, orthogonality, a small residual, or a low-rank sample does not by itself establish floating bitwise invariance.

T4 assumes the fixed D graph and numerical policy, the same legal initial state/inputs/schedule, serialized trusted API execution, bit-preserving storage, and unchanged private implementation/runtime. Arbitrary direct private mutation, monkeypatching, concurrent memory races, changed compilers/reduction trees, and hardware faults are outside this contract. Native BF16, GPU/GEMM, and a complete machine proof of the host stack are not certified. CPU FP32 tests are evidence for the performed primitive operations, not universal certification of every CPU backend.

No P2-A3 implementation or conclusion is included.

## Reproduction

From any working directory, using the environment specified by the main deliverable:

```bash
python /workspace/p2_a2/verify_review_checks.py
```

The script writes its own result file next to itself. It exercises P2-A2 and the declared imported arithmetic interfaces; it does not launch the P1 or P2-A1 verification suites.
