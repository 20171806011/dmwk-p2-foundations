## Counterexamples and the conclusions they block

| Counterexample | Reproducible evidence | Exact scope of the negative conclusion |
|---|---|---|
| Individually low-rank call-site spans can merge into full rank. | Exact suite `shared_call_counterexample`; independent review `merged_site_counterexamples`; T2 discussion. | A shared matrix must protect the union of all call sites in common physical coordinates. Per-site capacity cannot be reused independently without proof. |
| The thirds projector is not exactly representable, yet its decoded rounded row sums remain zero. | Numerical `quantized_projectors`; independent rounding records `thirds_projector_exact_stored_kernel_residual`; Numerical Analysis §2. | Projector nonrepresentability alone does not establish kernel leakage or absence of representable null directions. |
| Quantization can genuinely break a kernel. | Numerical suite uses `H=ones(6)`; independent oracle uses `H=(1,3)`. The latter decoded residuals are `(-1/256,-1/2048)` for BF16 and `(-1/16777216,-1/134217728)` for FP32. | Exact projection does not make a rounded projector exact on its protected span. Distinct examples deliberately avoid relying on the thirds fixture for this claim. |
| Exact zero dot product can execute to `-1`. | Numerical `zero_dot_and_optimizations`; independent `rounding`: row `(2^p,1,-2^p,-1)` with unit activations and separate ordered RNE. | A real/rational null product does not imply floating output equality. Changing reduction order can change the result. |
| FMA and separate operations disagree. | Numerical `zero_dot_and_optimizations`; Numerical Analysis §6. Fused output is explicitly a software exact-RNE reference. | Reassociation/FMA requires a separate contract or proof. This is not a claim of native FMA execution. |
| A representable ideal null update fails after weight storage. | Numerical `commit_and_capacity`, pointwise certificates, and independent rounding: `W=(2^p,0)`, ideal update `(1,-1)`, effective update `(0,-1)`. | The annihilation condition must not be checked only on the ideal proposal when the actual stored effect differs. |
| A zero floating residual at a basis activation fails at another legal activation in the same span. | Numerical `quantized_projectors`; independent `numerical_certificates`: rounded thirds projector gives zero at `ones(3)` but words `0x1` in each output at `eta*ones(3)`. | Testing a generating basis does not certify all legal finite-precision activations. Both activations are explicitly declared; no closure of the legal finite set under arbitrary real combinations is assumed. |
| Numerical rank can create false complement capacity or depend on conversion/threshold. | Numerical `svd`; independent `near_rank_exact_rank` and single/double default-rank comparison. Exact rank and converted-input rank are recorded separately. | SVD threshold rank is a diagnostic decision, not exact protected rank or a global capacity certificate. |
| Relative-only rounding bounds can fail under underflow. | Numerical `subnormal_and_rejections`; independent `subnormal_tie_local_error` and `invalid_gamma_bound_absent`. | The smallest positive subnormal times one-half rounds to zero. Exact absolute local-error accounting remains valid; an unsupported gamma bound is not issued. |
| An unstorable ideal increment can still have a valid finite final commit. | Numerical regression and independent `finite_sum_with_unstorable_ideal_increment_accepted`: `-Fmax+2Fmax=Fmax` before the one final rounding. | Optional stored-increment probes must not redefine the declared ideal final-rounding commit domain. Native add and ideal commit remain different operations. |

These are constructive negative examples with explicit arithmetic. Their purpose is to disprove the identified overbroad implication, not to imply that every projected update fails.

```bash
python /workspace/p2_a2/verify_projection.py --p1-root /workspace/dmwk-p1-foundations

```

The first command writes the aggregate; the second writes independent review results. They verify this A2 implementation and use the unchanged P1 arithmetic interfaces; they do not launch P1/P2-A1 stage suites. The main runner accepts an explicit alternative output path through `--output`.

BF16 results use **software exact-rational RNE**, not native BF16 hardware. FP32 arithmetic uses local CPU NumPy float32 scalar operations audited against exact rounding; the selected single-precision SVD dispatch is separately recorded. Zero arithmetic results are canonicalized, invalid special values are rejected according to the applicable interface, and the declared ordered multiply/add graph is fixed. A raw signed-zero interface is not conflated with rational equality or with the stricter structural update policy.

There is **no SMT proof, Lean/Coq machine proof, native BF16 certification, GPU validation, concurrent-memory proof, general dense-kernel authorization theorem, or general compiler refinement proof** in this round. A safe algebraic complement requires global activation provenance; a numerical certificate requires its explicit hypotheses; structural bitwise protection requires the fixed D graph and trusted API. No P2-A3 result is claimed.
