# B4 exact-D serial integration and read-only switching receipts

Saved before implementation; code waits for the mathematical checkpoint and settled dependency interfaces. Earlier research and frozen optimizer trajectories remain read-only.

## One publication for exact-D updates and the accepted history

The live fixture uses the unchanged B1 `structural_duplicate_v1` bank: first two columns fixed at I2, editable third column, both complete Boolean D call sites and synchronous XOR feedback. The selected gate remains `ALG_AND_BIT`. A target `(1,-1)` at legal A input e3 gives a concrete repeated-learning task; no universal learning benefit is claimed.

The B4 owner holds a private combined value containing a B1 kernel and an immutable accepted-update ledger. To stage an update, it deep-copies the owned B1 kernel, invokes B1 preparation and commit on that unexposed copy, constructs the new ledger, validates all bindings, and constructs the replacement combined value. Only then does it publish one owned pointer. No B1 update is first published and subsequently followed by a potentially refusing ledger write. Ticks likewise operate on a private copy and publish one replacement after the protected tick succeeds.

Prepared records bind the complete old combined snapshot, endpoints, optimizer state/config, protected q/ticks, versions, exact D graph/domain/policy/schedule, toy task, ledger and the request. A refusal preserves the entire owned combined snapshot. External diagnostics count attempts; rejected attempts are not written into the protected accepted ledger. Accepted update index, nonzero endpoint changes, optimizer time and D ticks are separately recorded. A zero stored change can be an accepted B1 transaction and must not be described as new functional progress.

This is a trusted serialized Python object model. No concurrency, malicious private-memory mutation, process-crash durability, allocation-failure atomicity of the host runtime, or hardware-fault protection is claimed. The private mutable B1 object is never exposed to a caller; the outer immutable ownership discipline supplies the modeled publication boundary.

## Read-only switching-budget evidence

The switching receipt is a separate type. It binds both complete physical-bank histories including unused/skipped versions, monotone version-selection schedules, actual stored biases, the fixed graph and every shared call, format/policy, initial relation and same-input history, finite horizon, full observations, joint tube/invariant proof and numerical budget ledger. It recomputes the switching core's proof against externally expected parameters and contexts. It grants no BIT/ALG or live B1/B4 authorization.

A full B4 snapshot may be carried as identity context, with a required schedule. This does not assert that the numerical comparison graph is the exact-D program or that unrelated scalar states are the B4 Boolean state. Direct endpoint accounting includes storage/optimizer effects once. A numerical budget cannot waive the existing exact gate or supply unsupported domain provenance.
