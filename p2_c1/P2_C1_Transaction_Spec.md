# P2-C1 compiled-program publication contract

The owner executes a trusted serial sequence of ticks and update requests for one specified Boolean FSM. It accepts a structural update when the **actual stored replacement** passes the compiled layout, numerical policy, full legal D domain and current-snapshot checks. Its pure compiler and execution prerequisites are specified in [Compiler interface](C1_Compiler_Interface.md). The finite-prefix proof appears in T6–T8 of [Theorems](P2_C1_Theorems.md).

## Owner and observations

Creation takes the complete source, budget, precision, declared initial A anchors, a legal initial-state index and an optimizer configuration. The owner reconstructs the compiler output from these inputs. If the caller supplies a compiled artifact, the owner requires exact canonical equality with that reconstructed value. This binds the IR, labelled ports, complete ordered calls, single physical bank, immutable cells, writable coordinates, zero biases, state/observation wiring, activation rules, format and input domains. An initial A anchor sets a column at compile time. Subsequent legal updates may change that column.

The owned snapshot includes immutable compilation context, endpoint words, source state, endpoint version, tick count, initial relation, task, optimizer configuration and moments, accepted-update and tick ledgers, administrative limits and implementation identities. The protected observation consists of the D source output and next state at each logical tick. Return values and snapshots are detached from mutable owned data. Successful updates publish their new weights and metadata while preserving the current D state and the tick counter. A tick snapshots one complete version, computes every output and next state from the old state, and publishes the complete successor. An accepted update increments the endpoint version even if storage rounding leaves the weights identical. The optimizer clock advances only on a successful optimizer update.

## Candidates and acceptance

1. The live owner checks its implementation fingerprints and recompares the artifact to the externally expected complete source and budget. Work starts from a private staged snapshot.
2. A direct endpoint request supplies canonical stored words. A direct AI increment can request a final structural mask or submit an unmasked direction for full endpoint verification. The latter choice retains the same fixed-cell acceptance policy.
3. For configured SGD or EMA momentum, form the complete optimizer increment first. Retain the proposed next optimizer state on the private copy and apply the row and column selectors to the final increment. Current optimizer support excludes clipping and weight decay. More general optimization algorithms require their own explicit order and state contract.
4. Form each new endpoint coefficient by adding the ideal increment to the exact decoded old coefficient, followed by rounding to the selected storage format. Validate every resulting word and each immutable D or cross-region cell. Recompute the actual increment by exact decoding and subtracting old from new. A directly supplied endpoint enters this validation without assuming an ideal increment.
5. Require the actual increment to vanish outside the editable block and on the three globally protected input coordinates. Execute both complete D state/input tables and compare summaries containing the full table digest, actual output/next-state words and every site's trace digest. This supplements the structural source/domain proof. The proof relies on immutable D operands and the complete reconstructed graph and does not assume digest comparisons alone establish bitwise identity.
6. Execute the complete legal A zero/basis domain. On success stage endpoint, optimizer, exact delta and rank, prefix delta and rank, A response/loss, D evidence, counts and ledger event. Administrative version and accepted-update limits may still refuse the proposed operation at this late stage.
7. A prepared candidate binds the full old owned snapshot and its digest, complete request, new weight words and version, proposed optimizer state, prepared event, unchanged D state and tick counter, implementation identities and schedules. The commit parser checks the bounded candidate envelope, rejects duplicate JSON keys and nonfinite tokens, and verifies exact canonical recomputation against the live snapshot. Only after receipt construction succeeds does one assignment publish the replacement owned bank.

A refused request publishes no staged object. The entire snapshot, including nonzero optimizer moments and ledgers, must remain byte-equivalent in the agreed serialization. A stale tick or old version changes the binding even if the current D state happens to have the same bits as before. A numerical or geometric diagnostic has no publication route. Unkeyed digests identify data supplied in a trusted context. Authentication, concurrent publication, crash durability and fault handling remain outside this model.

## Executed learning and rejection cases

The verification uses a one-bit feedback program with next state `q XOR u` and output `q` from the old snapshot. The compiled graph takes seven primitive D calls per tick. It uses a 4-by-4 matrix with 16 matrix words, four fixed bias words and two writable A cells. The full-output annihilator of the containing rank-three input space has dimension four. The editable block has dimension two, achievable individual rank one and full-basis response dimension two. The observed loss is half the exact squared error of the decoded A output at its first coordinate vector against the target (1,-1). The SGD rule uses learning rate 1/4 and the derivative of the corresponding real-valued linear loss. The finite-word execution supplies actual stored outputs and losses.

For each of 64 learning updates the test compares all four compiled D state/input rows directly, including every gate trace, to the original endpoint's executions. A Boolean XOR oracle checks pre-transition outputs and next state. The 256 full state/input comparisons encompass 1,792 gate-trace comparisons. The test also follows 64 paired feedback ticks using seeded inputs. All these D comparisons agreed. The basis response remains able to distinguish different A endpoints after the BF16 SGD plateau.

A separate 2-by-2 editable-block example applies two rank-one increments with independent input and output directions. The final baseline-relative rank is two. Its second increment leaves the first basis response unchanged. A stored endpoint with one maximum finite coefficient and an adjacent smallest positive subnormal returns both raw words on the corresponding basis input. An outward proposal that overflows is refused. An inward update is subsequently accepted from the same finite endpoint. The accepted direct edits preserve the optimizer clock.

The standalone run passed **1,156 checks**, including **54 intentional refusals** with exact whole-owner comparisons, using seed 20261114. Its 17 rehashed mutation paths per format cover source, graph, calls, domain, version, state, biases, activation, rounding policy, optimizer, effects and authority. Additional cases cover a stale tick and version, protected and cross-region writes, an illegal input, a read-only numerical claim and administrative exhaustion after private staging. The momentum fixture exercises nonzero moments in both fixed and editable coordinates. Rejection retains the old moments and ledgers. The main aggregate repeats this same suite; its cases should not be added to these counts as independent evidence. Details and measured runtime are in [transaction_results.json](transaction_results.json).

The complete D comparison concerns only the Boolean step domain of this compiled source and graph. The all-time conditional induction uses the source correspondence and Boolean closure proof. This experiment reports finite target improvement under the stated optimizer, storage format and input domain. Arbitrary dense A inputs, A-to-D feedback, universal learning performance, other compiled layouts and other arithmetic backends require additional evidence.
