# P2-B1 dependency errata and scope clarifications

The read-only inspection of the A4 handoff, records, theorem boundaries and necessary A1-A3 contracts found no predecessor error requiring a corrective copy. The inspection verified existing hashes and read interfaces; it did not rerun earlier suites. Original evidence remains unchanged.

The following B1 clarifications strengthen the new interface rather than amend previous results:

1. A3's pure complete-domain certificate can remain valid across legal state ticks while a weight version stays fixed. B1's combined weight/optimizer publication binds the entire old snapshot, including protected state and ticks. A tick after B1 preparation therefore requires preparation again. This prevents an optimizer commit from restoring an older D state.
2. Exact final-increment projection is not final-endpoint safety. Quantization can change the effective direction. BIT and ALG_AND_BIT are distinct acceptance claims, and a capacity/projection report grants neither by itself.
3. A canonical record and unkeyed digest provide identity and semantic consistency checks, not authentication of an original caller's intent. A coherently reissued valid request from a trusted caller is a different admissible candidate; no cryptographic anti-substitution property is claimed.
4. The structural layout previously supplied pure endpoint evaluations, not live publication authority. Any B1 structural transaction requires a new fixed descriptor, complete local coverage, state-invariant argument, endpoint checks and combined-publication proof.
5. A rank cap on one ideal increment, a rank cap on a persistent adapter relative to its fixed base, and the rank of an actual stored-endpoint difference are different constraints. None is silently substituted for another.

Any implementation defects found during this B1 round are to be recorded in the review with their corrections and affected reruns. A failed experimental attempt is not to be relabeled as a successful safety guarantee.
