# Coordinator handoff: B2 single-layer perturbation bounds

This is a next-stage plan, not B2 implementation. B1 stops after delivery for coordinator review. Continuing authorization does not require a new per-stage permission request.

## Required starting evidence

Read B1's Report, Definitions, Theorems, Evidence Map, Review, actual main/independent results and final integrity record. Preserve the read-only A1-A4 foundations. In particular retain global activation provenance, actual stored endpoint differences, selected ALG/BIT contract, fixed graph/policy and complete shared-site coverage. A finite low-rank sample is not a containment certificate.

## Strict B2 questions

1. Specify the single-layer object and observation before deriving a bound: affine or linear layer, bias policy, input set/norm, endpoint pair, intermediate precision and fixed reduction graph. Distinguish exact output difference from differences between two separately rounded executions. Protect full outputs or name any restricted ports explicitly.
2. Account separately for candidate generation, approximate projection or factors, optimizer arithmetic, and endpoint quantization. Use the actual decoded difference `W'-W`. A zero ideal residual or a floating basis test does not remove these errors.
3. Choose and justify absolute/relative/mixed bounds on a proved global domain. Treat near-zero outputs, cancellation, subnormals, overflow refusal, canonical zero and nonfinite values explicitly. Do not apply a standard relative-error-only model outside its hypotheses.
4. Preserve algorithm order and backend scope. Host AdamW proposal operations, software BF16, local audited FP32 and hypothetical fused/reassociated graphs are distinct. A bound for one graph is not a certificate for another.
5. Define what a nonzero bound authorizes, if anything. B1's BIT checker does not accept a bounded difference as bitwise equality. Turning a bound into exact equality needs a separate separation/lattice argument and complete coverage, with the A3 program-lifting assumptions still in force.
6. Retain B1's endpoint/optimizer transaction boundary. If a future bounded policy permits additional updates, name its changed claim and checker. Do not silently weaken existing BIT/ALG_AND_BIT contracts or reuse their labels.

## Proposed finite validation and retained boundaries

Derive the chosen bound before implementing it. Validate it against independently computed exact decoded references and actual declared floating operations on small complete domains, then use clearly labeled seeded cases. Preserve the thirds/subnormal basis-test failure, endpoint rounding loss, saturated storage, full-rank rounded equivalence and target-relation incompatibility as boundary cases. Include fixed shared call sites and state feedback only when their coverage and induction premises are actually supplied.

Report bound tightness, acceptance/refusal cost and observed arithmetic behavior separately from universal proofs. Toy A-loss improvement in B1 is not a transferable performance guarantee. GPU/native BF16, general concurrency, arbitrary compiler optimization, full long-term B4 training and the complete C series remain outside the inherited certification.
