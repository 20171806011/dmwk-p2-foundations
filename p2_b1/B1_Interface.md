# B1 reference interface and staged-publication contract

This interface is saved after the mathematical checkpoint and before implementation. All matrices use the read-only A2 `exact_projection.Matrix` type, with exact `Fraction` entries. A matrix is n output rows by d input columns. H has d rows and generates the protected span. None of the algebra helpers authorizes an endpoint commit.

## `constrained_updates.py`

- `project_direction(G, H) -> Matrix`: exact `G P_perp`.
- `nullspace_update(Z, H) -> Matrix`: `Z N.T`, where N is the deterministic exact basis of `ker(H.T)` and Z has n rows and c columns.
- `lowrank_update(L, R, H) -> Matrix`: `L R P_perp`, with L shape n-by-k and R shape k-by-d.
- `mask_direction(G, free_columns) -> Matrix`: retain the listed columns and zero the others.
- `clip_direction(G, mode="none", bound=None) -> (Matrix, audit)`: exact coordinate clipping for `element`; one common rational scalar obtained from host binary64 norm/sqrt for `global_norm`; `none` is identity. Global-norm clipping preserves an exact annihilator because the final multiplier is one scalar, but the reported norm threshold is numerical, not an exact irrational-norm theorem.
- Frozen `OptimizerConfig(kind, learning_rate, momentum=9/10, beta1=9/10, beta2=999/1000, epsilon=1/100000000, weight_decay=0, clip_mode="none", clip_bound=None)` accepts only integers/Fractions for scalar configuration. Kinds: `sgd`, `momentum`, `adamw`.
- Frozen `OptimizerState(step, m, v)`, and `initial_optimizer_state(n,d)`.
- `optimizer_proposal(W, gradient, state, config) -> Stage`: returns the raw increment and next optimizer state without endpoint quantization. `Stage` has `raw_increment`, `increment`, `next_state`, and JSON-compatible `audit` fields.
- `stage_optimizer(W, gradient, state, config, mode="none", H=None, free_columns=()) -> Stage`: modes `none`, `gradient_only`, `projected`, `structural`. Gradient-only mode projects before all optimizer operations; projected mode projects the entire final clipped increment; structural mode masks the entire final increment. The raw increment is retained for diagnosis.
- Serialization helpers `matrix_record`, `matrix_from_record`, `config_record`, `state_record`; these use numerator/denominator pairs, not lossy decimal strings.

The exact order is: optional gradient-only projection; optimizer moment calculation; parameter step; decoupled `-learning_rate*weight_decay*W`; increment clipping; optional final projection or mask. Momentum uses `m_new=beta*m+(1-beta)*g`. SGD/momentum, decay and coordinate clipping use exact rational arithmetic. AdamW uses explicitly ordered finite Python binary64 operations for moment products/sums, bias correction, square root, denominator, division and parameter step, then decodes each resulting float exactly to `Fraction`. The literal Python `beta ** step` and `math.sqrt` belong to this host proposal specification; they are not certified as correctly rounded mathematical power/square-root functions or as reproducible across arbitrary platforms. Its final exact rational decay, clipping and restriction are separately reported. No host optimizer operation is labeled BF16/FP32 protected execution. Optimizer state advances only if the endpoint transaction is accepted; step, weight version and tick counters are bounded by 2^63-1 and exhaustion refuses.

## `optimizer_kernel.py`

- `OptimizerKernel(model_id, fmt, config, claim="ALG_AND_BIT", initial_words=None, initial_state_word=0)` owns one immutable `CombinedBank(weights, q_word, ticks, weight_version, optimizer_state)`. It deep-copies the configuration and never exposes its private optimizer-state objects through snapshots.
- Models: unchanged A3 `duplicate_feedback_v1`, `split_feedback_v1`, and new `structural_duplicate_v1`. Claims: `BIT` or `ALG_AND_BIT`.
- `model_descriptor(model_id,fmt)` defines the complete domain, protected graph, numerical policy, input/state invariant, A interface and schedule. It is a fixed trusted registry, not a caller-provided sample domain.
- `global_generators(model_id,fmt) -> Matrix`, `initial_weights(model_id,fmt)`, `evaluate_a(weights,activation,fmt,model_id)` and `evaluate_d(weights,q,u,fmt,model_id)` expose pure reference evaluations.
- `ai_request(direction, restriction="projected") -> dict`; `optimizer_request(gradient, restriction="projected") -> dict`. Requests contain exact rational matrices and fixed string choices only. AI restrictions: `none`, `projected`, `structural`; optimizer restrictions: `projected`, `structural`. Unconstrained and gradient-only optimizer baselines use `stage_optimizer` offline, not live authorization.
- `kernel.preview(request) -> dict`: pure staged proposal, endpoint and next-state data, explicitly uncertified. It may fail validation/quantization; it never publishes.
- `kernel.prepare(request) -> str`: canonical JSON of a complete staged candidate and safety certificate; fails with `UpdateRejected` if unsupported or unsafe. The record binds the full old combined snapshot, exact request, optimizer configuration/state, endpoint, source identities, graph/domain/policy/schedule and claim.
- `kernel.commit(prepared_text) -> dict`: strictly parses and completely recomputes the prepared candidate/certificate against the current snapshot, then publishes one new `CombinedBank`. A successful weight commit increments `weight_version` once, preserves q/ticks and includes the staged optimizer state. An AI update retains optimizer state unchanged.
- `kernel.snapshot() -> dict`: canonical complete snapshot for rollback checks. `kernel.tick(u_word) -> dict` updates q and ticks in one new bank using the same old-state snapshot and no A feedback.

Any D tick after preparation invalidates the B1 candidate because q/ticks are included in the old snapshot binding. This is stricter than an A3 full-domain certificate alone and prevents overwriting a later protected state at combined publication. A stale candidate, unsupported domain/graph, changed config, inconsistent request/certificate, unsafe endpoint or failed numerical operation leaves the entire combined bank unchanged. Canonical recomputation and unkeyed hashes establish semantic consistency, not caller identity or original intent: a coherently reissued new request with valid complete evidence is another authorized trusted-caller proposal. No registry or secret authenticates its historical origin. This is a trusted single-threaded API theorem, not crash consistency, malicious-memory protection or general concurrent atomicity.

Dense endpoint checks call A3's unchanged pure `make_certificate`/`check_certificate`; they do not perform a separate A3 live commit. The B1 owner publishes its combined bank only after the pure check and optional exact ALG check succeed.

The structural bank is `((1,0,theta_0),(0,1,theta_1))`, initially theta=(1,0). Protected state/input activations are `(q,q,0)` and `(u,u,0)` for all Boolean q,u. The fixed sparse D graph reads only the first two columns and uses the inherited exact XOR primitive on the first outputs, all from one old snapshot. A legal A interface includes e3, e1 and zero; e3 exposes theta. The new finite descriptor and checker verify all four state/input combinations, immutable first columns, canonical stored words and fixed zero bias before publication. The protected arithmetic read-exclusion argument applies after admitted-bank validation; it does not claim identical entire host traces.

`lowrank_update` bounds the exact per-proposal increment only. This interface does not claim that a rounded effective endpoint difference, a cumulative trajectory or a persistent adapter difference inherits the same rank cap. Preview records report both the exact proposal rank and the actual decoded effective-difference rank. The selected live claim is ALG/BIT, not an additional rank-cap authorization.
